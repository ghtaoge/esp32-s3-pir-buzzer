当前发布版本为 **1.0.3，HC-SR505 三脚模块专用配置**：PIR OUT→GPIO13，蜂鸣器→GPIO7。
1.0.2 修复了未使用的雷达串口初始化、旧 NVS 雷达模式恢复以及两端遗留的雷达选择/接线提示。

## 自动化软件检查

- ESP32-S3 完整编译及链接成功：静态 RAM 102404 / 327680 字节（31.3%），应用 Flash 849878 / 6553600 字节（13.0%）。这不包括运行时 BLE 动态堆，需看实板遥测。
- `npm test`：62 项通过，0 失败。包含共享协议、PC、微信原生 BLE mock 与页面状态测试。
- `npm run test:firmware`：7 组原生 C++ 测试通过。
  - GPIO/PWM 适配器模拟：静态空闲和极性、按需 PWM、反复空闲不重复 IO、强制停止、部分初始化/变调/清理失败及恢复；四种声音均在休止和截止时解除 PWM。
  - 四种声音边界、音高钳制、统一截止、取消和计时回绕。
  - 配置类型/范围/未知键校验、原子拒绝与 JSON 往返。
  - 精确帧容量、溢出整帧丢弃、CRC、覆盖、清除水位。
  - 持续活动限时停止、平静恢复、去抖、静音/撤防、测试、离线和回绕。
  - HC 硬件配置迁移：旧模式转 PIR，保留其他设置，持久化往返和重复迁移幂等；拒绝雷达模式及参数。
  - 历史雷达解析库的兼容回归仍保留，但 HC 固件不会运行这些硬件路径。
- 独立检查最终 ELF：没有 `HardwareSerial::begin`、雷达处理或雷达配置启动入口符号，UART17/18 未被当前固件初始化。
- PC 参数使用差异提交，未收到设备确认不显示成功；微信端拒绝时保留草稿。
- 两端支持无源低电平驱动，但在旧固件上提交该选项会明确要求升级；输出失败记录可以同步、持久化、恢复和显示，不能混同已启动鸣叫。
- 超时/断连不会自动重放写操作。新连接使用独立 session nonce，旧连接同 id 的迟到回复被忽略。
- JS/JSON 及微信 WXML 事件绑定/表达式做过静态检查；这不等于微信开发工具编译。
- 公开源文件扫描检查密钥模式、私有微信配置、构建产物；提交前另跑 `git diff --check`。
- Arduino 文件夹与实际固件/全部头文件通过同步检查，避免分发过期草图。

## PC 浏览器

3. 手动立即停止，主动测试不计入活动触发数。
4. 参数修改等待 ACK，可设置响铃时长；硬件固定 HC-SR505，不提供传感器切换或雷达控件。
5. 四种声音预设分别保存并试听，短总时长也会按时停止。
6. 历史区分活动与手动测试；CSV 下载成功；清空需确认及成功 ACK。

9. 1.0.3 针对性复查：无源极性可编辑，保存后重新读取仍生效；手动测试截止、活动持高时的 LOW 恢复提示以及 375px 参数页均通过，0 个页面运行时异常。

## 性能与资源

实现约束：

- 2048 字节固定接收帧，BLE 20 字节有序分片；溢出丢到换行，不能把尾部当新指令。
- 客户端最多 16 个待处理命令；设备接收/回复/存储队列均有固定上限。
- 状态每 200ms 合并发送，回复在完整帧边界优先；慢读端不能把帧中间截断后继续拼新帧。
- 感应与鸣叫按非阻塞计时执行；Flash/NVS 写入在独立任务，BLE 回调不等待文件系统。
- 设备只存事件，客户端缓存最多 1000 条；PC 每页 50 条、微信每次最多显示最近 100 条。
- 有效持久化后才广播日志；存储失败/队列满通过状态显示，不隐瞒数据丢失。

本机一次软件基准结果（同时存在其他开发负载，数值仅为该次测量）：

| 工作负载 | 结果 |
| --- | --- |
| 100000 个状态帧，20 字节分片解码 | 1527ms，约 65473 帧/秒 |
| 解码器持有容量 | 固定 2048 字节，GC 后未观察到随消息数增长的保留堆 |
| 10000 次内存内串行 RPC | 791ms，结束时 pending/queue 均为 0 |
| C++ 10000000 次模拟感应 tick | 58.205ms；25000 个预期活动片段全部匹配 |
| 100000 次 CRC/日志插入/保留扫描 | 538.671ms；RAM 日志镜像固定 40032 字节 |

复现：`npm run benchmark`、`npm run benchmark:firmware`。
这些是主机软件吞吐/逻辑测量，**不能换算成 ESP32 实板循环耗时、BLE 无线速率、Flash 停顿或传感器响应时间**。
实板上可查看 freeHeap/minFreeHeap/loopMaxUs/queueDrops/txDrops/storageErrors。

## 实物与微信平台边界

已经连接真实 ESP32-S3 并经 USB 完成 1.0.3 烧录，写入哈希校验通过。已回读版本、HC 硬件配置和以下状态：

- 旧版连续 35 秒的 176 个读数均为 HIGH，触发计数为 1，状态为等待释放；用户断开 HC OUT 后，同一 GPIO13 恢复 LOW 和待命。这证明输入读取会响应接线变化，不能据此认定模块供电和输出健康。
- 新版空闲 `buzzerPwmAttached=false`，手动测试期间为 true，设定 3000ms 后首次停止状态通知出现在启动 ACK 后约 3124ms。通知每 200ms 一次，这不是示波器测得的实际停鸣延迟。
- 测试后 `sounding=false/outputOn=false/buzzerPwmAttached=false`，强制停止也成功；配置未改动，手动测试未增加人体活动次数。
- 当次 `queueDrops=0/txDrops=0/storageErrors=0`，输出和存储就绪；最低空闲堆约 135416 字节，记录到的最大循环间隔约 21351µs。此单次读数不能当作长期最坏情况保证。

以下实物验收尚未完成：

- HC-SR505 实际检测范围、动作响应、保持/恢复时间与环境干扰。
- GPIO7 上所购无源蜂鸣器的额定电压、驱动极性、空闲异响是否消失、音量/音高/四预设声音及实际停鸣延迟。软件状态和 PWM 总线占用不能代替用户听音或电气测量。
- 真正断电重启、掉电写入与损坏文件系统恢复。
- Android/iOS 微信真机蓝牙权限、连接、重连和 AppID 平台配置。
- 手机 BLE 与 PC USB 同时连接时的现场操作与长期运行。

连接开发板后建议依次验证：保存配置并重启 → 触发且限时停止 → 持续活动不续响 →
平静后再触发 → 静音仍有记录 → 四预设试听 → 断线继续记录并重连补同步 →
清除后序号不重置 → 确认 HC 固件拒绝其他传感器模式、参数错误不假报成功。

公开仓库提供可运行源码与检查步骤，不把尚未现场确认的部分标成已验证。
