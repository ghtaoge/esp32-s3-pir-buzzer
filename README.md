# ESP32-S3 人体感应蜂鸣器

纯硬件应用：上电立即开始读取 HC-SR501，检测到有效触发后，无源蜂鸣器只响 **2 秒**并自动停止。传感器持续输出高电平不会续响；低电平稳定 100 毫秒且本次鸣叫结束后，才能接受下一次触发。不需要屏幕、手机、Wi-Fi 或蓝牙。

程序没有 60 秒等待，但 HC-SR501 自身刚上电时可能不稳定，因此初期可能误触发。高电平稳定 30 毫秒后触发，以过滤短暂毛刺；主循环每约 2 毫秒检查一次输入。GPIO3 使用内部下拉，避免 OUT 线接触不良时输入悬空。

软件不会改变传感器自身的保持延时和封锁期。如果走动时模块 OUT 没有产生新的高电平变化，程序无法从这一根数字信号中判断又发生了一次移动。先确认供电、型号和 TIME / 灵敏度设置，再判断是否需要更快的传感器。

## 接线

| HC-SR501 | ESP32-S3 |
| --- | --- |
| VCC | 5V |
| GND | GND |
| OUT | GPIO3 |

**HC-SR501 的 VCC 用 5V 供电，OUT 是约 3.3V 的数字信号。** 本项目使用常见带板载稳压器的 HC-SR501，不建议从开发板 3V3 给它供电；供电不足可能造成输出异常、误触发或保持高电平。

蜂鸣器沿用现有接法，控制信号接 GPIO7，电源按模块额定电压，所有模块共地。GPIO 编号不是排针序号。HC-SR501 常见输出为 3.3V，不能把 5V 电源直接接入 GPIO。

GPIO7 输出 2kHz PWM，停止时输出低电平，适用于已接好的非反相驱动蜂鸣器模块。未知电流的裸电磁蜂鸣器需通过三极管驱动。

## Arduino IDE 使用

1. 打开 `arduino/pir_buzzer/pir_buzzer.ino`，完整程序在这一个文件内，无需额外库。
2. 使用 Espressif `esp32` 开发板包 **3.x**，选择 **ESP32S3 Dev Module** 和开发板对应串口。
3. N16R8 配置：Flash Size 为 **16MB**，PSRAM 为 **OPI PSRAM**，USB CDC On Boot 为 **Enabled**。
4. 点击上传。串口监视器波特率为 **115200**，程序不等待串口连接。

上传会替换板上现有固件。上电立即检测，不等待一分钟。每次触发响 2 秒后停止，传感器仍为高电平也不会一直叫。HC-SR501 的 TIME 保持延时会影响下一次何时能重新触发，初次测试建议调到最短。HC-SR501 检测移动，不能可靠检测静止在场。

串口每 2 秒打印一次 `PIR=HIGH/LOW armed=0/1 buzzer=ON/OFF events=... PWM=OK mode=AUTO`。`armed=0` 且 `PIR=HIGH` 表示本次触发已处理，等待传感器回到低电平。保持高电平期间 `buzzer=OFF` 是正常的限时停止。

串口诊断命令（115200 波特率）：

- `?`：查询状态，并对 GPIO7 引脚输入回读采样 3 毫秒，打印高/低电平样本数量。
- `t`：暂时暂停自动鸣叫，独立测试蜂鸣器 2 秒；测试结束后保持静音，模式显示 `MANUAL_TEST`。
- `a`：恢复自动感应，模式显示 `AUTO`。上电始终默认自动模式。

鸣叫时 GPIO7 采样应同时出现高、低电平，停止时应仅为低电平。采样用于确认引脚有电平切换，不用于测量精确频率或声压。测试完成后记得发 `a` 恢复自动感应。

## PlatformIO 使用

打开本项目目录，环境为 `esp32-s3-n16r8`：

```powershell
pio run
pio device list
pio run --target upload --upload-port COM你的串口号
```

固件源文件为 `src/main.cpp`。修改后运行 `node tools/prepare-arduino.js`，同步生成 Arduino 草图。

## 行为测试

本机安装 g++ 后，可在 PowerShell 运行：

```powershell
New-Item -ItemType Directory -Path '.local' -Force | Out-Null
g++ -std=c++11 -Wall -Wextra -Werror -I include tests/motion_alarm_test.cpp -o .local/motion-alarm-test.exe
if ($LASTEXITCODE -eq 0) { & '.\.local\motion-alarm-test.exe' }
```

测试覆盖上电立即检测、30 毫秒高电平确认、100 毫秒低电平恢复、持续高电平时 2 秒强制停止、短毛刺过滤、再次触发和计时器回绕。

## 当前验证状态

当前代码已通过行为测试与完整 ESP32 编译，并已烧录到 ESP32-S3，写入数据的哈希校验通过。实板已验证独立 2 秒测试音、多次 PIR 自动触发和 GPIO7 引脚电平切换。

**当前仍是调试版本：现场反馈反应慢、间歇未触发的问题尚未完全定位。** 被测模块的新触发信号曾约每 5 秒出现一次；软件缩短了输入确认时间，但不能消除模块自身的保持延时和封锁期，也不能据此承诺每次动作都会立即触发。模块型号、调节设置及现场接线仍需确认。
